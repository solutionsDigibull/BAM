# 0033 — The UI bundle is part of the certified Workflow: BAM delivers it, SRIM shows only it

- Status: Accepted
- Date: 2026-11-18
- Related: epic #748, issue #857 (WG-25), issue #768 (WG-20, generates the bundle), refines [0028](0028-workflow-mcp-server-repo-first-bifrost-registry.md) (decisions 3, 4 and 7), [0031](0031-srim-walks-the-workflow-dag-with-temporal.md), [0032](0032-staging-replaces-the-pre-commit-preview.md), [TD §11](../design/11-manifest-design.md)

## Context

A Workflow has a server (one FastMCP image, [0028](0028-workflow-mcp-server-repo-first-bifrost-registry.md)),
a router ([0031](0031-srim-walks-the-workflow-dag-with-temporal.md)) and, since [0032](0032-staging-replaces-the-pre-commit-preview.md),
a complete UI that the FDE sees in Staging. Until now the manifest had no place for that UI, certification
did not check one and the registry did not return one. [0031](0031-srim-walks-the-workflow-dag-with-temporal.md)
left "how a Workflow's UI is packaged and shown by SRIM" open. The owner decided on 2026-11-18 that BAM always
delivers the UI as a bundle and that SRIM hosts and shows only that bundle.

## Decision

1. **BAM's UI bundle only.** Every Workflow BAM builds ships a UI bundle, generated by BAM (#768). SRIM hosts
   and shows that bundle and nothing else: there is **no generic schema renderer in SRIM**, and a Workflow
   without a bundle is not shown.
2. **The bundle is part of the certified artifact.** The Workflow manifest has an optional `ui_bundle` entry
   in the style of `mcp_server`: `version` (MAJOR.0.PATCH), `digest` (`sha256:` of the packaged bundle),
   `entry_file` (the `.html` page that loads first, a relative path inside the bundle), `allowed_hosts`
   (the only hosts the UI may reach: DNS names, or `*.` and a DNS name; no scheme, port, path or IP address;
   the list may be empty) and `workflow_server` (the `mcp_server.name` it belongs to). It is covered by the
   frozen manifest hash, and it needs the `mcp_server` entry.
3. **Old manifests do not move.** The field is unset on every manifest built before this ADR, `dump()` leaves
   it out, so frozen manifests and the ISA14 fixtures validate and keep their hashes. "SBAM-built" means the
   manifest carries an `mcp_server` image; for those the bundle is required **by certification**, not by the
   schema (the same approach as the router rule of 0031).
4. **Certification evidence `UI_BUNDLE`.** One row in `gate_results` with a `workflow_id` and no Sub-Skill, on
   the bundle hash (without the `sha256:` prefix, like the code gates). It records: the bundle is present, its
   packaged digest equals `ui_bundle.digest` of the manifest, and every declared host is legal. Certifying a
   Workflow SBAM built needs the newest row to be PASSED on exactly the manifest's digest, like
   `IMPORT_RESOLUTION`, `REPO_LICENCE`, `DEPENDENCY_VULN` and `MCP_COMPLIANCE`; otherwise the reasons are
   `MISSING_EVIDENCE:UI_BUNDLE`, `GATE_FAILED:UI_BUNDLE` or `EVIDENCE_HASH_MISMATCH:UI_BUNDLE`. It is not a
   Sub-Skill gate, so the Sub-Skill checklist does not ask for it. The bundle is certified in the sandbox,
   and Staging shows the bundle with this exact digest ([0032](0032-staging-replaces-the-pre-commit-preview.md)).
5. **The registry returns the certified entry.** Registering needs a passed `UI_BUNDLE` row on the manifest's
   digest (nothing uncertified becomes visible). The registered entry keeps a copy of `ui_bundle` (nullable:
   entries registered before this ADR have none), and the lookup returns it with the same digest that was
   certified, for the current and for a superseded version.
6. **Generating the bundle and hosting it are not decided here.** #768 generates it (pattern, files, drift
   checks); how SRIM or Staging serves it is open ([0032](0032-staging-replaces-the-pre-commit-preview.md)).

## Consequences

- **Contract change, small and first.** `UiBundleEntry`, `WorkflowManifest.ui_bundle`, `GateName.UI_BUNDLE`,
  `BuildsResponse.workflow_gates` (so the workbench shows the row) and `RegisteredWorkflow.ui_bundle`. One
  migration widens the `gate_results.gate` check and adds `registered_workflows.ui_bundle`.
- **What this refines.** 0028 decision 3 (the manifest records the server) now also records its UI; decision 4
  (what is registered) now includes the bundle entry. Earlier ADRs keep their text.
- **Open.** The Workflow-level certification activity is still a stub, so `certification_reasons` is the rule it
  must call; nothing wires it into the pipeline here (no stage is added to ProjectPipeline).
