## Bugs

### 1. The tusd post-finish hook returns 500 (`StaleDataError`). Reproducible.

- **Seen:** 6 times in run 1 and 2 times in run 2, on `POST /internal/tusd/hooks`. API log:
  `"msg": "unhandled exception", "exc_type": "StaleDataError", "exc_at": "persistence.py:949"`, then
  `status: 500`. Uploads still succeed only because tusd retries the hook.
- **When:** multi-file uploads (E05 valid mix, E06 rejects, the walkthrough's 3-file upload).
- **Probable cause:**
  - `post_finish` in `server/api/sbam_api/ingest/service.py` first calls `_finish_claims`, which loads
    the reservation with `reservation_by_id(session, slot_id)` and no lock (line ~310).
  - Then it calls `ReservationRepository.get_for_update` (`ingest/repository.py:192`), which selects the
    same row `FOR UPDATE`. SQLAlchemy returns the object already loaded in the session, with its **old**
    attribute values, because the query has no `populate_existing`.
  - When tusd sends the same hook twice at once, the second request:
    - sees `status == CREATED`, so it skips the "retried hook" check;
    - writes with an old `row_version`, so the UPDATE matches 0 rows, raises `StaleDataError`, and
      returns 500.
- **Fix:** in `ReservationRepository.get_for_update`, add
  `.execution_options(populate_existing=True)`. Add a unit test that loads the slot, changes it in a
  second session, then calls `get_for_update` and expects the new status and row version.

### 2. The dev web container keeps old dependencies after a pull, so pages return 500

- **Seen:** after merging `dev`, the **SOW, Workflows and FDE Registry pages returned 500**:
  `Module not found: Can't resolve 'dompurify'` (imported by
  `client/src/app/(fde)/projects/[projectId]/sow/sow-schema.ts`).
- **Cause:** in `compose/compose.override.yaml`, `sbam-web` mounts the named volume
  `web_node_modules:/app/client/node_modules`.
  - Docker fills a named volume from the image only when the volume is created.
  - After that, the volume hides the image's `node_modules`, so `up --build` installs the new package
    into the image, but the container still sees the old copy.
  - `pnpm install` inside the container fails too: the non-root user can't write the corepack cache
    (`EACCES … /home/sbam/.cache/node/corepack`).
- **Workaround used:** `docker compose … rm -sf sbam-web && docker volume rm sbam_web_node_modules &&
  docker compose … up -d sbam-web`.
- **Fix options (D2, compose owner):** either stamp the volume with a lockfile hash and reinstall at
  start when it changes, or drop the named volume and use an anonymous one recreated with
  `--renew-anon-volumes`. Until then, document the workaround in `docs/DEVELOPER_GUIDE.md`.
- **Impact:** every developer hits this after any client dependency change.

### 3. Langfuse export is on, but Langfuse isn't running, so the buffer keeps growing

- **Seen:** worker-llm logs `langfuse export failed (ConnectError); 2 events buffered`, then 4, then 6,
  and `langfuse project not checked (ConnectError)`.
- **Cause:** the updated local `.env` sets the Langfuse variables, but the `obs` profile isn't started.
- **Check:** whether the buffer in `sbam_workers.llm.trace` is bounded. If it isn't, a long-running
  worker grows its memory.
- **Local fix:** start `obs` (`-f compose/compose.obs.yaml`), or leave `LANGFUSE_HOST` empty.

## Setup findings

- **New required env vars on `dev`:**
  - `MOCK_CONTROL_TOKEN`: `docker compose up` fails without it
    (`required variable MOCK_CONTROL_TOKEN is missing a value`).
  - `COGNEE_USER_SECRET`: the A-09 change removed its built-in default, and it must be **at least 32
    characters**. Without it, worker-knowledge stays unhealthy
    (`health FAILED COGNEE_MISCONFIGURED: COGNEE_USER_SECRET must be at least 32 characters`).
  - Both are now set in the local `.env`. Anyone with an older `.env` hits the same thing after pulling.
- **`make` isn't installed on Windows.** Use the raw compose command:
  `docker compose --env-file compose/.env -f compose/compose.yaml -f compose/compose.override.yaml -f compose/compose.analytics.yaml up -d --build --wait`
- **`KEYCLOAK_PORT` moved to 8089 in the local `.env`.**
  - `client/e2e/keycloak.spec.ts` defaults to `http://localhost:8080`, so t08 fails in its cleanup
    poll unless `E2E_KEYCLOAK_URL=http://localhost:8089` is set.
  - The spec could read `KEYCLOAK_PORT` instead.
- **t08 calls compose with only `-f compose/compose.yaml`.** That works for `stop`/`start`, but it
  needs every variable to be set in `.env`.

## Test harness findings

- **Playwright output inside `client/` can reload the dev pages in a loop.**
  - `sbam-web` runs `next dev` with `client/` bind-mounted and `WATCHPACK_POLLING=true`.
  - Playwright writes `test-results/` (videos, traces) into `client/`, which triggers Fast Refresh
    rebuilds. The login page then reloads every ~1 s, and Keycloak tests time out with
    `navigated to /login-fde` over and over.
  - Fix: run with `--output` outside `client/` (or set `outputDir` in `playwright.config.ts`), then
    restart `sbam-web`.
- **A cold dev server is slow.** The first visit to each route compiles it, and that sends rebuild
  events to every open tab. The first test of a run (t01) failed this way once. Warm up the routes
  first, or test a prod build.
- **Windows-only test failures (not bugs):**
  - `test_a01_t01_prod_worker_serves_no_stub` and `test_e16_2_preflight_runs_on_the_llm_queues` import
    `sbam_workers.ingest.isolated_child`, which imports `resource` (POSIX only).
  - `test_a21b_t01_isolated_result_equals_in_process_result` uses `os.killpg` (POSIX only).
  - `test_llm_mock_rubric.py` needs `node` on PATH (the slim uv image has none).
  - Run the backend suite on Linux (CI, WSL2, or `ghcr.io/astral-sh/uv:*-python3.12-bookworm` with
    `UV_PROJECT_ENVIRONMENT=/tmp/venv`, so the Windows `.venv` isn't overwritten).
- **Client unit tests time out under load.** `token-refresh`, `masters-screen`, `knowledge-panel` and
  `test-panel` fail when Docker builds run at the same time, and pass alone.
- **Stack tests leave data behind when a run dies.** E04, E06, E09 and the walkthrough archive their
  project in `finally`, but a crashed browser skips that. 14 leftover `e2e-*` projects were archived
  by hand.
- **Memory is the main limit.**
  - With the full stack up, free RAM dropped to ~2 GB. Chromium crashed (`Target crashed`,
    `0xC0000142`) and Claude Code stopped long background runs three times.
  - worker-knowledge was at **1.83 of its 2 GiB** limit after one run, close to being killed.
  - worker-llm's watchfiles crashed once with `Cannot allocate memory (os error 12)`.

**UX notes:**
- **404s are retried.** The data provider retries a 404 several times before showing the not-found or
  empty state. A 404 means "not found" or "not yet", so it shouldn't be retried. Set `retry` to skip
  4xx.
- **Tab pages show `Project <uuid>` as the title.** Only the overview shows the project name.
- **The knowledge entity counts differ.** The summary says 71 entities, and the explorer says "22 of 22
  entities". Check whether these count different things (mentions vs unique nodes) and label them.
